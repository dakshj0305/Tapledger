1. Scope

Vellum is a static, local-first personal finance web application. The app is designed to keep financial records in browser storage on the device where the app is used. It does not provide a bank connection, fetch bank balances or send ledger records to a Vellum application server.

2. Information stored on your device

When you use the relevant features, Vellum stores the following records in IndexedDB in your browser profile:

StoreInformationWhy it is used
transactionsTransaction ID, type, amount in integer paise, currency, category, merchant/source, note, date, account references, source label and created/updated timestamps.Ledger, account calculations, budgets, charts and analysis.

Amounts are stored as integer paise to reduce floating-point rounding issues. The app does not ask for your name, email address, phone number, bank login, card number, card PIN or UPI PIN.

3. Browser storage and offline cache

Financial records are stored in IndexedDB under the database name tapledger-db. The service worker uses Cache Storage for the static application shell (HTML, CSS, JavaScript, manifest, legal pages and local icons) so the interface can load offline after the first successful cache installation. The service-worker cache is application code, not a backup of your transactions.

Vellum source does not use localStorage, sessionStorage or application cookies. Browser storage can be removed by clearing site data in your browser; doing so may permanently remove local financial records. Export a JSON backup before clearing browser data or changing devices.

4. Information sent to hosting providers

When you open the site hosted on GitHub Pages, your browser makes a normal web request to the hosting provider. The hosting provider may receive technical request information such as the requested URL, IP address, browser/device details and request time as part of delivering and securing the website. The details and retention of provider-side logs are controlled by the hosting provider, not by this static application. Review the hosting provider's own privacy documentation. Vellum's application code does not send your transaction, account, budget or goal records to GitHub Pages.

5. NFC shortcuts and URL parameters

An NFC tag stores a URL shortcut, such as ?a=1 for an expense form or ?i=1 for an income form. Legacy ?add=1 expense links are also recognized. The app reads the action and removes the query string from the visible address bar after loading. Do not put amounts, merchant names, account names or other personal financial details into a URL or NFC tag: URL paths and query strings are sent as part of the initial web request and may be visible to the host.

6. Optional voice entry

Voice entry is optional and is off unless you explicitly opt in through the in-app notice. If you opt in and start voice recognition, the browser's Web Speech API may send live microphone audio or speech data to a browser/vendor speech service for recognition. Vellum does not choose or control that service, its processing location or retention. Those details depend on the browser and provider and are not verified by Vellum. Vellum does not save an audio recording in its own financial database. The recognized text is used to prefill the transaction form; it is not saved to the ledger until you review and submit the form.

You can withdraw your Vellum voice preference in Data & settings. Withdrawal prevents Vellum from starting voice recognition without asking again. It cannot recall audio already sent to a browser/vendor service; use that provider's controls for any request relating to its processing.

7. Analytics, advertising and cookies

The supplied Vellum application source contains no analytics tracker, advertising script, social widget or cookie-setting code. Vellum does not intentionally set or read cookies. Essential application behavior uses IndexedDB and the service-worker Cache Storage API instead. A browser or hosting provider may process its own technical data outside the Vellum application; inspect browser developer tools and the host's documentation for provider-level behavior.

8. Export, restore and deletion

You can export transactions as CSV and download a JSON backup. Restore imports supported Vellum, Cairn and TapLedger backup records by merging records by their identifiers; it is not a destructive replace. The in-app delete-all action removes local transaction, budget, goal, account, legacy-expense and settings records from the Vellum database, then recreates only the minimal default account/migration state needed for an empty application. The static app-shell cache may remain so the interface can still load offline. For removal of all browser site data, use the browser's site-data controls for this site.

9. Children and sensitive information

Vellum is a personal finance tool and is not designed to collect identity documents, health records, payment credentials or government identifiers. Do not enter such information in merchant or note fields. The publisher must set an appropriate age and child-use policy after legal review; this source audit does not verify age-related legal requirements.
